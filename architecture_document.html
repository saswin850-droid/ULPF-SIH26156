Universal Log Pre-processing Framework (ULPF)

System Architecture & Technical Specification · SIH 2026 (Problem Statement SIH26156 · NTRO)
Theme: Blockchain & Cybersecurity

1. Executive Summary & Problem Framing

Enterprise IT and defense environments generate millions of heterogeneous event logs daily across firewalls, Linux/Windows servers, identity providers, and container clusters in conflicting structures (RFC3164 Syslog, JSON, CSV, CEF ArcSight, LEEF QRadar, Cisco ASA, FortiGate). Modern SOC and SIEM pipelines suffer from three fundamental failures:

  • Information Destruction: Traditional ETL normalization drops unmapped vendor attributes, destroying post-incident forensic value.
  • Broken Evidentiary Custody: Normalized entries in downstream databases lack mathematical verification linking back to original raw bytes.
  • High Ingestion Debt: Onboarding a new hardware vendor or service format requires heavy script rewrites and pipeline downtime.

ULPF addresses this with a zero-loss, air-gapped log pre-processing pipeline that transforms arbitrary log streams into an OCSF-aligned canonical schema while guaranteeing mathematical traceability via deterministic SHA-256 raw-byte hashing.

3. Core Architectural Principles

Lossless Forensics & Cryptographic Audit

Every event computes SHA-256(raw_bytes) at the exact entrypoint over binary input bytes. The raw payload is preserved verbatim. External investigators with only original disks can independently re-hash files to verify zero tampering.

Extensible Plug-and-Play Registry

Parsers subclass abstract BaseParser (can_parse, parse). A guaranteed FallbackParser terminates the chain, ensuring zero event loss across unknown formats.

5. High-Throughput Big Data Production Roadmap

While the hackathon prototype executes a self-contained SQLite storage layer for zero-dependency evaluation, the decoupled modular design directly maps to a distributed big data architecture capable of processing billions of events/day: 

   [ Edge Telemetry Agents ] ──► [ Apache Kafka / Redpanda Cluster ] (Distributed Partitioned Buffer)
                                                  │
                                                  ▼
                              [ Horizontally Scaled Stateless Workers ]
                              (Kubernetes Pods running ULPF ParserRegistry)
                                                  │
                  ┌───────────────────────────────┴───────────────────────────────┐
                  ▼                                                               ▼
       [ Hot Tier: OpenSearch / ClickHouse ]                       [ Cold Tier: Apache Iceberg / S3 ]
       Sub-second SOC Search & Anomaly Detection                  Lossless Parquet + Merkle Root Audit Ledger
  • Decoupled Ingestion: Kafka partitioned topics isolate collector bursts from normalization processing.
  • Stateless Scaling: Worker pods running ParserRegistry scale linearly based on queue lag without database locking.
  • Cryptographic Batch Sealing: At scale, individual SHA-256 hashes are assembled into hourly Merkle Trees, providing mathematical proof of log integrity for national security and compliance.

6. Architectural Trade-offs & Honest Scope

  • Targeted Schema vs Full OCSF: Full OCSF specifies ~70 classes and hundreds of fields. ULPF intentionally scopes to an OCSF-aligned core + extra catch-all to guarantee low latency and zero data drop.
  • Embedded Storage vs Distributed Cluster: SQLite was selected for the local evaluation build to guarantee out-of-the-box air-gapped execution without requiring a multi-node cluster setup during judging.
  • CSV Severity Integrity: Network logs lacking explicit severity are retained as null rather than artificially inferred from action, preventing false-positive skew in downstream security analytics.
